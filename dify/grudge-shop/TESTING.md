# 验证与试玩

## A. 无模型的真实记忆闭环

启动 README 中的两个服务，并在第三个终端配置相同的 `GATEWAY_TOKEN`：

```bash
python check_dsl.py
python verify.py
```

verify 每次生成新的随机测试玩家，无需清除已有记忆。步骤为：新玩家召回应为空 → 保存“量子罐头”恶作剧 → 新的 HTTP 请求以同玩家召回 → 确认实际内容包含该恶作剧 → 不同玩家召回应为空 → 错误 token 应返回401。

证据保存在 `evidence/powercontext-roundtrip.json`，包含真实写入 records、scope ID、prepare 返回内容。店主台词是测试夹具，此测试验证实际指定技术的读写与复用，不验证 Dify 或模型。

## B. Dify 完整试玩（已在Dify Cloud实测，可按此复现）

初始条件：使用新的终端用户身份，或在网关设置全新的 `GAME_NAMESPACE` 后重启。没有预置记忆。模型使用 README 指定配置或记录最终替代模型。

1. 在 Dify 预览输入：“第一次来，借口罐头怎么卖？”预期：初次见面，不凭空虚构旧事，介绍奇物，输出态度和三个选项。记录九节点成功，写入返回非空 records。
2. 输入：“我把借口罐头偷偷换成空气，标签写着量子罐头。”预期：店主围绕该恶作剧做出反应，本轮写入成功。
3. 在同一浏览器、同一 Dify 终端用户身份下新建对话（不是仅清空显示），输入：“我又来了，你还认得我吗？”预期：`翻开黑历史` 返回 `ready`，content 包含第二步实际行动，LLM 输入确实引用该 content，回复提及量子罐头或换空气的恶作剧。此时 Dify 内置记忆关闭，证明历史来自 PowerContext。
4. 输入：“我承认上次换了罐头，对不起，我免费帮你整理货架。”预期：店主对既有恶作剧和本轮补偿同时作出反应，可以心软，但不强制一句话就通关。
5. 在上轮道歉后输入“我补回罐头，整理好货架，继续为你做诚实宣传。现在我来领取熟客徽章。”预期：明确显示“友好结局·本店最不放心的熟客”及获得徽章；也可通过反复恶作剧触发黑名单结局。未触发结局时由模型即兴回复，结局触发时使用网关已写入记忆的固定结算文本。
6. 换为另一个终端用户身份输入第三步内容。预期：独立 scope，无第一位玩家的量子罐头历史。

每一步保存输入、完整回复、节点状态、HTTP 召回/写入的非敏感结果。切勿把 token 和模型凭据放进截图。

## C. 失败及重置

- 输入引号、换行、反斜杠和emoji，应正确编码成 JSON，不应损坏请求体；check_dsl.py 覆盖此场景。
- 网关 token 不匹配：HTTP401；记忆服务停机：HTTP502；工作流不得给出本轮已保存的假成功回复。
- 新玩家第一次 prepare 返回 empty 正常，LLM 应按初次见面继续。
- 超长输入明确失败；长对局回忆有6000字节预算，不验收无限历史。
- 重置使用新的测试玩家或更换 `GAME_NAMESPACE`，这是开始一个新世界，旧记录仍保留。不要为了重跑删除作者或其他玩家的数据。

当前实际执行范围见 STATUS.md。B部分在Dify Cloud已完成首次光临、恶作剧、跨对话回忆、补偿和熟客结局，公开入口也已实测；不同玩家隔离通过真实公网网关验证，未用两个独立浏览器身份重跑完整游戏。规则回归可执行 `python test_game_rules.py`。
