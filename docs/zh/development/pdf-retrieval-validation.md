# PDF 证据页检索验证

本次修复以提交 `9c8d65990e0e8415e7401db396f404a8fb966c30` 为基线。产品变更限定在 `src/powercontext/sources/_pdf_search.py`，保留其他赛题实现、PDF 全页解析、Source 身份和精确引用合同。

## 已复现的问题

公开 PDF 自测检查完整页数、入库和引用回查，没有检查 FinanceBench 标注质量及证据页召回门槛。因此公开自测通过不等于第 4 题的全部验收条件通过。

独立评分复现了以下检索缺陷：

- 标题 `Consolidated Balance Shee\nt` 被 PDF 拆成两行，旧标题识别无法将该页识别为资产负债表。
- 资本密集度、速动比率、利润率和税率等问题需要相应财务报表或附注；仅按字面词项排序容易把风险段落和重复术语排在前面。
- 多公司放在同一 Scope 时，跨公司的全局词项权重会过度奖励反复出现的公司名。公司名应确定财报范围，不能作为页内相关性的主要证据。
- 并购、自然增长和业务分部的表达不完全一致，需要通用会计词项扩展和分部披露标题识别。

平台未提供失败日志，因此不能断言每次零分都来自同一断言；上述缺陷均已通过独立数据或构造用例实际复现。

## 修复行为

完整标题匹配会忽略布局空白，同时保留标题位置和完整匹配限制，避免将正文中提到报表的句子当成报表本身。检索先按问题中的公司和期间定位报告，再在该报告内计算 IDF，移除已经用于定位报告的公司名词项。通用会计查询扩展和报表/附注类型用于保证多种必要证据进入候选结果。

返回值仍取自当前 scoped Memory 中真实、活动的 MemoryEntry，使用原始 citation，按 Source 身份去重，并受 limit 限制。不读取答案、标注文件或预解析资产，不保存公司、问题到页码的映射。

## 独立质量结果

在原始 FinanceBench 固定 revision 的原 PDF 上执行，标注只由产品目录之外的独立评分器使用，不作为检索输入。每条返回引用实际经 `memory.get` 回查。

| 验证组 | 实际页数 / 问题数 | 基线证据页召回 | 修复后证据页召回 |
|---|---:|---:|---:|
| PepsiCo 公开组 | 503 页 / 5 问题 | 7/8 = 87.5% | 7/8 = 87.5% |
| 10 份报告同 Scope 的多文档组 | 1529 页 / 7 问题 | 6/11 = 54.5% | 11/11 = 100% |
| 另 3 份完整报告的扩展组 | 571 页 / 21 问题 | 8/23 = 34.8% | 18/23 = 78.3% |

三组修复后的召回率均超过 70%。这些已验证标注的最低证据词项召回为 0.982456，最低整页 F1 为 0.974832，均超过 0.95。PDF 解析器未改变，所有页面继续按原物理页返回；公开完整页数、空白页、权限标记、原子失败、修订身份和重启后的引用由公开验收及产品回归测试验证。

这不是对组织方隐藏组的复刻或满分承诺。组织方的隐藏分组和全页冻结词项计数未分发，最终成绩仍须使用修复后的 commit 提测确认。
